Model selection

AutoGLM-Phone-9B vs. Multilingual: choose for the interface your agent will see.

Both released model variants support the same Phone Agent framework. The practical choice is not a benchmark race: it is whether the mobile interfaces and tasks your agent must read are Chinese-only or include English and other languages.

Published Jul 25, 20264 minute readDeployment planning

Use a test device and validate the complete interaction path before applying either model to a real workflow.

The short answer

Chinese applicationsStart with AutoGLM-Phone-9B, which the official documentation says is optimized for Chinese mobile apps.
English or mixed UIStart with AutoGLM-Phone-9B-Multilingual, described as supporting English scenarios and applications containing other languages.
Unknown mixTest the multilingual variant first, then compare action traces on the same fixed task set.

What stays the same

Both variants are used through the Open-AutoGLM Phone Agent framework. The framework connects to Android through ADB or to HarmonyOS through HDC, reads a screen through a vision-language model, plans an action sequence, and performs device operations. The developer setup, safety boundaries, and need for manual handling of authentication are the same.

What should drive your choice

Decision factorPhone-9BPhone-9B-Multilingual
Official positioningOptimized for Chinese mobile applications.Supports English scenarios and other language content.
Best first testA workflow whose instructions, labels, and app content are Chinese.A workflow containing English labels, multilingual content, or switching locales.
Deployment pathServe the selected model with a compatible endpoint, then point the agent to it.Same framework; official documentation includes a vLLM serving example for this model.
How to validateRun the same small, reversible workflow several times. Compare whether the model identifies the intended element, preserves task intent, and stops at the correct boundary.

Do not infer language support from a single successful demo. Evaluate screens with the fonts, app layouts, permission dialogs, and task phrasing used in your actual environment. Model selection is an operational test, not a label-only decision.

A compact evaluation plan

  1. Build a 10-task set with no credentials, payments, or destructive actions.
  2. Include the exact languages, app labels, and common modal dialogs the agent will encounter.
  3. Run each task with clear stop conditions and capture screenshots and traces.
  4. Score successful completion, unexpected actions, manual takeovers, and refusal or stop behavior separately.
  5. Use the model that is more reliable on your interface mix, not the model that is simply easier to install.
