Open-source update

AutoGLM-Phone-9B is open source. Here is what you need to run it.

The Phone Agent framework exposes a practical route from a natural-language request to supervised phone actions. It uses screen understanding, planning, and Android Debug Bridge or HarmonyOS Device Connector control instead of a proprietary cloud-phone workflow.

Published Dec 9, 2025Updated Jul 25, 20267 minute read

Official project screenshot, linked from the Open-AutoGLM documentation.

Two model choicesThe base Phone-9B model targets Chinese mobile applications; the Multilingual version is intended for English and other language content.
Device controlAndroid connects through ADB. HarmonyOS support uses HDC. Both require developer tooling and device authorization.
Serving optionsRun your own OpenAI-compatible service through vLLM or use a listed hosted model provider.

What changed

The open project and model cards published in December 2025 make the Phone Agent stack available for research and development. The project describes its model as a vision-language agent that reads the active screen, plans the next operation, and executes a workflow. It also includes confirmation for sensitive actions and manual takeover for authentication steps.

Important scope: this is a developer framework, not a promise of unattended access to every app. Login, MFA, payment, and identity checks should remain user-controlled checkpoints.

Minimum deployment path

  1. Use Python 3.10 or later and install the project requirements.
  2. For Android, install platform-tools, enable USB debugging, and validate the connection with adb devices. For HarmonyOS, configure HDC and verify the target connection.
  3. Install the required Android input method when using ADB text entry.
  4. Start an OpenAI-compatible model endpoint. The official documentation provides vLLM parameters for the multilingual model.
  5. Run one harmless, observable task before enabling any production workflow.

Run with controls, not blind autonomy

Use a test device or emulator for experimentation. Keep USB or remote ADB access limited to your trusted network. Start with read-only or reversible tasks such as opening an application and searching a public phrase. Require user approval before any action that sends data, changes account settings, spends money, or transmits credentials.

For automation teams, pair each task with a clear stop condition, a human review step, and retained screenshots or logs. These controls matter more than a high task-completion rate because the agent acts through the same interfaces a person uses.
